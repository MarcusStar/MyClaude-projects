## 二、产品概述

### 2.1 产品背景

随着个人消费场景日益复杂（移动支付、信用卡、分期付款等），越来越多的人希望清晰掌握自己的资金流向。但市面上的记账产品普遍存在以下问题：

- **记账流程繁琐**：打开 App → 选择分类 → 输入金额 → 保存，步骤多、耗时长，用户难以坚持；
- **功能臃肿**：社区、理财推荐、广告推送等功能干扰核心记账体验；
- **数据不可控**：数据存储在云端，用户对隐私有顾虑，且难以导出自有数据。

记账的本质是「**低摩擦记录 + 清晰复盘**」。本产品回归记账核心，主打 **3 秒完成一笔记账**，帮助用户以最低成本养成记账习惯，并通过统计报表洞察自己的消费结构。

### 2.2 产品定位

> 一款**轻量、快速、无广告**的个人消费记录与管理工具。

**一句话价值主张**：3 秒记一笔，月底不糊涂。

### 2.3 产品目标

| 目标类型 | 描述 | 衡量指标 |
| --- | --- | --- |
| 用户目标 | 快速记录每笔消费，随时了解钱花在哪 | 单笔记账耗时 ≤ 3 秒 |
| 产品目标（MVP） | 跑通「记账 → 查看 → 统计」核心闭环 | 次周留存率 ≥ 40% |
| 产品目标（长期） | 成为用户每日必开的财务助手 | 月活跃天数 ≥ 20 天/用户 |
| 体验目标 | 无广告、无冗余推送、隐私安全 | 崩溃率 < 0.1% |

### 2.4 产品范围说明

**本期（V1.0 MVP）做**：

- 支出/收入快速记账
- 消费分类管理（预设 + 自定义）
- 流水明细查看、编辑、删除
- 月度统计报表（分类占比、收支趋势）
- 月度预算设置与超支提醒

**本期不做（后续版本规划）**：

- ❌ 多人共享账本 / 家庭账本
- ❌ 银行账户、支付宝/微信账单自动同步导入
- ❌ 投资理财、借贷管理
- ❌ 社区、内容推荐
- ❌ 多币种、多账本

## 三、用户分析

### 3.1 目标用户画像

| 画像维度 | 描述 |
| --- | --- |
| 年龄 | 18～40 岁为主 |
| 身份 | 学生、职场新人、白领、自由职业者 |
| 特征 | 有储蓄/理财意愿，但缺乏对自身消费的系统认知 |
| 设备 | 智能手机为主（碎片时间记账），PC 为辅（复盘统计） |
| 记账经验 | 多数尝试过记账但半途而废（嫌麻烦） |

### 3.2 典型用户角色（Persona）

**角色 A：小林，26 岁，互联网运营**

- 每月工资到账即开始「无感消费」，月底常疑惑「钱去哪了」；
- 曾下载 3 款记账 App，均因记账太麻烦放弃；
- 期望：打开就能记，两步以内完成；周末花 5 分钟看一眼本周消费分布。

**角色 B：小雨，21 岁，大学生**

- 生活费固定（每月 2000 元），经常月中就超支；
- 期望：设置月度预算，快超支时能收到提醒；能按分类看哪部分花多了（如奶茶、外卖）。

### 3.3 核心使用场景

| 场景编号 | 场景描述 | 发生频率 | 核心诉求 |
| --- | --- | --- | --- |
| S1 | 买完咖啡/午餐后，掏手机快速记一笔 | 每天 3～8 次 | 快、少步骤 |
| S2 | 发工资当天，记录一笔收入 | 每月 1～2 次 | 简单录入大额收入 |
| S3 | 睡前翻看今天记了哪些账，补记漏掉的消费 | 每天 1 次 | 按时间轴浏览、可编辑 |
| S4 | 月初查看上月消费报表，复盘消费结构 | 每月 1 次 | 图表清晰、分类占比一目了然 |
| S5 | 月中消费接近预算，收到提醒后控制支出 | 每月 0～数次 | 预算阈值提醒 |
| S6 | 记错金额/分类，需要修改或删除 | 每周 0～数次 | 编辑便捷 |

### 3.4 用户痛点与产品机会

| 痛点 | 现有产品的问题 | 本产品的解法 |
| --- | --- | --- |
| 记账步骤太多，坚持不下来 | 打开后需多层跳转才能记账 | 首页常驻悬浮「+」按钮，金额键盘前置，默认今天+常用分类 |
| 分类太复杂 | 几十个分类，选择困难 | 预设 12 个高频分类，支持自定义，常用分类置顶 |
| 广告与推送骚扰 | 开屏广告、理财推荐 | 承诺无广告、无营销推送 |
| 报表看不懂 | 图表花哨但无结论 | 报表突出「Top3 消费分类」与环比变化等结论性信息 |

### 4.2 功能优先级定义

| 优先级 | 定义 | 说明 |
| --- | --- | --- |

| P2 | 增强功能 | 可延后至 V1.1 |

### 4.3 功能需求详细说明

#### FR-01 记支出（P0）

**功能描述**：用户以最少的操作记录一笔支出。

**页面入口**：

- 首页悬浮「+」按钮（全局常驻）；
- 首页快捷记账卡片。

**交互流程**：

```
点击「+」 → 弹出记账面板（默认「支出」Tab）
→ 输入金额（数字键盘自动唤起）
→ 选择分类（默认选中上次使用的分类）
→ （可选）选择日期（默认今天）、填写备注
→ 点击「保存」 → 面板收起，Toast 提示「已保存」
```

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 金额为必填，支持两位小数，单笔上限 9,999,999.99 |
| R2 | 金额为 0 或非法字符时，「保存」按钮置灰不可点击 |
| R3 | 分类为必填，默认选中「上次使用分类」，首次使用默认「餐饮」 |
| R4 | 日期默认为当天，可修改范围为过去 5 年内～今天（不支持记未来的账） |
| R5 | 备注为选填，上限 50 字 |
| R6 | 保存成功后面板自动关闭；连续记账时支持「保存并继续记一笔」 |
| R7 | 无网络时支持本地保存，联网后自动同步（若开启云同步） |

**验收标准**：从点击「+」到完成保存，熟练用户操作不超过 3 秒 / 3 次点击。

---

#### FR-02 记收入（P0）

**功能描述**：记录工资、奖金、理财收益等收入。

**交互流程**：与记支出一致，记账面板切换至「收入」Tab。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 收入分类预设：工资、奖金、理财收益、兼职、红包、报销、其他 |
| R2 | 其余规则与 FR-01 一致 |

---

#### FR-03 流水列表（P0）

**功能描述**：按时间倒序展示所有账目，按天分组，供用户浏览与核对。

**页面元素**：

- 顶部：当月收支汇总条（本月支出 / 本月收入 / 结余）；
- 列表：按日期分组，每组显示「日期 + 星期 + 当日支出小计 + 当日收入小计」；
- 每条流水显示：分类图标、分类名、备注（无备注则显示分类名）、金额（支出红色/-，收入绿色/+）、时间。

**交互**：

- 点击单条流水 → 进入流水详情页（可编辑、删除）；
- 左滑单条流水 → 快捷「删除」；
- 下拉刷新；上滑加载更多（每页 30 条）。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 删除需二次确认弹窗：「删除后不可恢复，确认删除这笔账目吗？」 |
| R2 | 今日日期显示「今天」，昨日显示「昨天」，其余显示「MM月DD日」 |
| R3 | 无数据时展示空状态插画 + 引导按钮「记一笔」 |

---

#### FR-04 流水筛选与搜索（P1）

**功能描述**：帮助用户快速定位目标流水。

**功能点**：

- 按时间范围筛选（本月 / 上月 / 近三个月 / 自定义区间）；
- 按收支类型筛选（全部 / 支出 / 收入）;
- 按分类筛选（单选或多选）；
- 关键词搜索（匹配备注与分类名）。

**业务规则**：筛选条件支持组合生效；清除筛选一键恢复默认。

---

#### FR-05 编辑流水（P0）

**功能描述**：修改已保存流水的金额、分类、日期、备注。

**交互流程**：流水详情页 → 点击「编辑」 → 复用记账面板（回填原数据） → 保存。

**业务规则**：编辑保存后列表、统计数据实时更新。

---

#### FR-06 统计报表（P0）

**功能描述**：以图表形式展示消费结构，帮助用户复盘。

**页面结构（月度统计页）**：

1. **收支总览卡片**：本月总支出、总收入、结余；环比上月变化（↑/↓ 百分比）；
2. **分类占比图**（饼图/环形图）：各支出分类占比，按金额降序；点击扇区显示「分类名 + 金额 + 占比%」；列表区展示 Top 分类排行（分类名、金额、占比条）；
3. **每日支出趋势图**（柱状图）：本月每天支出金额，点击柱子显示当日明细入口；
4. **支出分类明细**：点击某分类 → 进入该分类下的流水列表。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 默认统计当前自然月，可左右切换月份 |
| R2 | 统计范围包含已编辑流水的最新数据 |
| R3 | 分类超过 8 个时，尾部合并为「其他」展示 |
| R4 | 环比计算：(本月支出 - 上月支出) / 上月支出 × 100%；上月无数据时不展示环比 |

---

#### FR-07 预算管理（P1）

**功能描述**：设置月度支出预算，实时跟踪使用进度，超支前提醒。

**功能点**：

- 设置/修改月度总预算（默认不设置，未设置时首页不显示预算卡片）；
- 首页预算卡片：预算金额、已用金额、剩余金额、进度条；
- 进度条颜色规则：使用 < 70% 绿色，70%～90% 橙色，> 90% 红色；
- 阈值提醒：当月支出达到预算的 80% 和 100% 时，各推送一次本地通知。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 预算按自然月生效，每月 1 日自动重置进度 |
| R2 | 每个阈值提醒每月仅触发一次，避免骚扰 |
| R3 | 已用金额 = 当月支出流水合计（不含收入、不含转账） |

---

#### FR-08 分类管理（P1）

**功能描述**：用户可管理自己的收支分类。

**功能点**：

- 查看分类列表（预设分类 + 自定义分类）；
- 新增自定义分类：名称（≤ 6 字）+ 图标 + 颜色；
- 编辑、删除自定义分类；
- 分类排序（拖拽调整顺序，记账面板按此顺序展示）。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 预设分类可改名、隐藏，但不可删除 |
| R2 | 自定义分类删除时，若已有流水使用该分类：弹窗提示「该分类下已有 N 笔流水，删除后将归入'其他'分类」 |
| R3 | 支出/收入分类独立管理，各自上限 30 个 |

---

#### FR-09 数据导出（P2）

**功能描述**：将流水数据导出为 CSV 文件，保障用户数据自主权。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 支持选择导出时间范围 |
| R2 | CSV 字段：日期、时间、类型（支出/收入）、分类、金额、备注 |
| R3 | 导出成功后提供「分享/保存至文件」入口 |

---

#### FR-10 记账提醒（P2）

**功能描述**：每日固定时间本地提醒用户记账（默认关闭）。

**业务规则**：

| 编号 | 规则 |
| --- | --- |
| R1 | 用户可自定义提醒时间（默认 22:00） |
| R2 | 当天已有记账行为时，不发送提醒 |
| R3 | 仅使用本地通知，不涉及服务端推送 |

## 五、非功能需求

| 类别 | 需求描述 |
| --- | --- |
| 性能 | App 冷启动 ≤ 2 秒；记账面板弹出 ≤ 300ms；流水列表滚动帧率 ≥ 55fps；统计图表渲染 ≤ 1 秒 |

| 无障碍 | 金额输入支持大字号模式；图表数据提供列表形式备选 |
| 离线能力 | 无网络时全部核心功能（记账、查看、统计）可正常使用 |

## 六、数据模型设计（概要）

### 6.1 核心实体

**流水表（transaction）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String(UUID) | 主键 |
| type | Enum | expense（支出）/ income（收入） |
| amount | Decimal(10,2) | 金额 |
| category_id | String | 分类 ID |
| note | String(50) | 备注，可空 |
| occurred_at | Datetime | 账目发生时间 |
| created_at / updated_at | Datetime | 创建/更新时间 |
| is_deleted | Boolean | 软删除标记 |

**分类表（category）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String(UUID) | 主键 |
| name | String(6) | 分类名 |
| type | Enum | expense / income |
| icon | String | 图标标识 |
| color | String | 颜色值 |
| sort_order | Integer | 排序权重 |
| is_preset | Boolean | 是否预设分类 |
| is_hidden | Boolean | 是否隐藏 |

**预算表（budget）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String | 主键 |
| month | String(YYYY-MM) | 生效月份 |
| amount | Decimal(10,2) | 预算金额 |
| notified_80 / notified_100 | Boolean | 阈值提醒是否已发送 |

### 6.2 数据量预估与性能设计

- 单用户日均 5～10 笔流水，年数据量约 3000 条，本地 SQLite 完全可承载；
- 流水表按 `occurred_at` 建立索引；统计表按月预聚合缓存，编辑流水后失效重算。

## 八、埋点与数据指标

### 8.1 核心北极星指标

> **周记账笔数（Weekly Transactions per User）**——反映用户是否持续使用产品完成核心价值。

### 8.2 关键埋点事件

| 事件名 | 触发时机 | 携带参数 |
| --- | --- | --- |
| record_panel_open | 打开记账面板 | 入口来源（悬浮按钮/空状态/提醒） |
| record_save | 保存成功 | 类型、分类、耗时（面板打开→保存） |
| record_cancel | 面板关闭未保存 | 已输入状态 |
| stat_page_view | 进入统计页 | 月份 |
| budget_set | 设置预算 | 金额区间 |
| budget_alert_click | 点击超支提醒 | 阈值（80%/100%） |
| transaction_delete | 删除流水 | 分类 |
| export_complete | 导出完成 | 时间范围 |

### 8.3 数据看板关注项

- 激活率：注册后 24h 内完成首笔记账的比例（目标 ≥ 60%）；
- 留存率：次日 ≥ 45%，7 日 ≥ 30%，30 日 ≥ 20%；
- 记账耗时中位数（目标 ≤ 5 秒）；
- 面板打开后放弃率（目标 ≤ 15%，过高说明流程有摩擦）。

## 十、风险与应对

| 风险 | 等级 | 描述 | 应对措施 |
| --- | --- | --- | --- |
| 用户难以坚持记账 | 高 | 记账类产品普遍留存低 | 极致简化流程；提醒策略；周报推送消费洞察提升回访动机 |
| 账单自动导入合规风险 | 中 | 读取第三方账单可能涉及授权与合规问题 | V1.0 不做自动导入；V1.2 采用用户手动导出 CSV 再导入的合规路径 |
| 数据丢失 | 高 | 本地存储损坏或换机导致数据丢失 | V1.0 提供手动导出备份；V2.0 提供云同步 |
| 分类体系不符合用户习惯 | 中 | 预设分类覆盖不足 | 支持自定义分类；上线后根据「其他」分类占比迭代预设分类 |
| 统计图表性能 | 低 | 多年数据聚合变慢 | 按月预聚合缓存，明细懒加载 |

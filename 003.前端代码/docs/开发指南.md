# 随手记账 · 前端开发指南

本目录是「随手记账」MVP（V1.0）的前端实现，视觉与交互以 `002.产品原型/expense-tracker/` 中的原型稿为准，
功能范围以 `001.产品经理PRD/PRD-个人消费记账产品需求文档.md` 为准。

---

## 一、技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 视图层 | 原生 HTML + Tailwind Play CDN | 零构建，双击 `index.html` 之外用本地服务器打开即可 |
| 脚本 | 原生 ES Module | 每个页面一个 module，浏览器原生支持，无打包器 |
| 图标 | Iconify (`iconify-icon` 自定义元素) | 使用 `ph:` 前缀的 Phosphor 图标 |
| 样式 | CSS 变量 + 语义化组件类 | `tokens.css` 定义设计变量，`components.css` 定义组件 |
| 数据 | localStorage + 内存降级 | key = `ledger:v1`，由 `core/store.js` 统一读写 |

> **为什么需要本地服务器**：ES Module 在 `file://` 协议下会被 CORS 拦截。
> 启动方式：`node serve.js`，然后访问 <http://localhost:5173>。

## 三、分层约定

```
pages/*.html  ──►  js/pages/*.js  ──►  js/components/*  ──►  js/core/*
   页面挂载         页面业务逻辑        可复用 UI            基础设施
```

**铁律**

1. 页面脚本**不得**直接读写 `localStorage`；一切读写走 `core/store.js`。
2. 页面脚本**不得**硬编码颜色；一律用 `var(--c-*)` 或 `tokens.css` 中的变量。
3. 页面跳转**不得**写死路径；一律用 `constants.js` 的 `ROUTES`。
4. 业务规则（金额上限、备注长度、日期范围等）**不得**散落在页面里；用 `constants.js` 的 `RULES`。
5. 通用视觉单元**不得**在页面里各写一份；先看 `components.css` 有没有，没有再新增组件类。
6. 账目数据走 `core/store.js`，账号数据走 `core/auth.js`，两者互不干扰。

## 四、页面脚本标准写法

```js
/**
 * 页面：xxx —— PRD P-xx / FR-xx
 * ------------------------------------------------------------------
 * 一句话说明这个页面做什么。
 */

import { h, icon } from '../core/dom.js';
import { createPage } from '../components/shell.js';
import { store } from '../core/store.js';
import { ROUTES } from '../core/constants.js';

function init() {
  const page = createPage({
    title: '页面标题',
    back: ROUTES.home,     // 二级页传返回地址；一级页不传
    tab: 'home',           // 三个主 Tab 页才传
    fab: true,             // 需要悬浮记账按钮时传
  });

  page.body.append(/* 页面内容 */);

  init();
}
```

> **每个页面都必须写 `if (!page) return;`**：`createPage()` 在未登录时会跳转到登录页
> 并返回 `null`，此时若继续执行就会在空对象上报错。详见「六、账号与登录」。

### `createPage(options)` 参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string | 顶栏标题 |
| `subtitle` | string | 顶栏副标题（可选） |
| `back` | string | 返回目标地址；传了就显示返回按钮 |
| `tab` | string | 底部导航激活项：`home` / `statistics` / `settings` |
| `action` | HTMLElement | 顶栏右侧操作按钮 |
| `fab` | boolean | 是否显示悬浮「+」记账按钮 |

返回 `{ frame, header, body, setTitle, showToast, go }`。

## 六、账号与登录（core/auth.js）

### 数据存放

账号数据存在独立的 localStorage 键 `ledger:v1:auth`，与账目数据（`ledger:v1`）分开：

- 「清除全部数据」只清账目，**不会**注销账号；
- 退出登录只清会话，**不会**删除账号。

```js
{
  accounts: [{ id, account, nickname, avatar, salt, passwordHash, createdAt, lastLoginAt }],
  session:  { accountId, loginAt, expiresAt } | null
}
```

### 密码处理

密码**从不明文落盘**。注册时生成 16 字节随机盐，计算 `SHA-256(盐 + 密码)` 后只保存哈希与盐。
`crypto.subtle` 不可用时（通过局域网 IP 访问等非安全上下文）降级为简易哈希，功能不中断。

> 注意：SHA-256 + 随机盐是演示级的强度，不是 bcrypt / Argon2 这类专用 KDF。
> 若要用于真实产品，需要换成慢哈希并加失败次数限制。

### API 速查

| 方法 | 说明 |
| --- | --- |
| `auth.isRegistered()` | 是否已注册过账号（决定登录页显示「登录」还是「注册」） |
| `auth.isLoggedIn()` | 是否有有效登录态（同步，门禁用它） |
| `auth.getAccount()` | 当前账号信息（不含密码字段） |
| `auth.register({account, nickname, password, avatar})` | 注册并自动登录 → `{ok, message?, account?}` |
| `auth.login({account, password})` | 登录 → `{ok, message?, account?}` |
| `auth.logout()` | 退出登录（清会话，保留账号） |
| `auth.updateProfile({nickname, avatar})` | 改昵称 / 头像 |
| `auth.changePassword({oldPassword, newPassword})` | 改密码 |
| `auth.redirectToLogin(redirect?)` | 跳转到登录页（登录后回到 `redirect`） |

### 登录门禁怎么生效

门禁做在 `components/shell.js` 的 `createPage()` 里——所有页面都经过它，所以只有一处需要维护：

```js
// createPage 内部
if (!isPublic && !auth.isLoggedIn()) {
  auth.redirectToLogin();
  return null;      // ← 返回 null，页面必须提前退出
}
```

因此每个页面脚本的开头都要有：

```js
const page = createPage({ ... });
if (!page) return;   // 未登录时已被重定向到登录页
```

新增页面时**不要漏掉这行**，否则未登录时会在空 `page` 上抛异常。
登录页自己传 `public: true` 跳过门禁（`login.js` 不走 `createPage`，直接搭自己的布局）。

## 十、代码风格

- 注释与界面文案使用中文；变量名、函数名使用英文。
- 每个文件顶部写一段块注释，说明用途与对应的 PRD 编号。
- 优先使用 `h()` 构造 DOM，避免拼接 `innerHTML` 字符串。
- 事件一律用 `addEventListener` / `onclick` 显式绑定，不写内联 `onclick="..."` 字符串。
- 金额一律经 `format.js` 格式化后展示，不手写 `toFixed`。
- 单个函数建议不超过 60 行；超出就拆成「构建 DOM」+「绑定事件」两段。

## 十一、新增一个页面的步骤

1. 在 `pages/` 下建 `xxx.html`（复制 `home.html`，改 `<title>` 与 `<script type="module">`）。
2. 在 `assets/js/pages/` 下建 `xxx.js`，按第四节的标准写法实现，
   **并记得写 `if (!page) return;`（登录门禁守卫）**。
3. 若页面不在主 Tab 上，`constants.js` 的 `ROUTES` 里登记，并在入口页放一个跳转入口。
4. 跑 `node serve.js` 打开验证。

## 十二、几个容易踩的坑

### 1. Iconify 脚本必须带 `defer`

```html
<script defer src="https://code.iconify.design/iconify-icon/2.1.0/iconify-icon.min.js"></script>
```

Iconify v2 的 web component 只渲染**脚本执行时已经存在于 DOM 中**的 `<iconify-icon>` 元素。
若把脚本写成普通的 `<script src>`（放在 `<head>`），它会在 `<body>` 解析前执行，
于是 HTML 里静态写死的图标全部渲染成空白；只有 JS 动态创建的图标正常。
加上 `defer` 让脚本在文档解析完成后执行，静态图标即可正常显示。

### 2. 弹层要挂到 `.app-frame` 内部

弹层（Sheet / Modal / Toast）必须用 `getOverlayHost()` 挂载，不能直接 `document.body.append`。
否则在宽屏下弹层会撑满整个视口，而不是限制在手机画板内。

### 3. 页面容器要有确定高度

`#app` 已在 `base.css` 中设置 `height: 100%`。若改成 auto，
`.app-frame` 的 `height: 100%` 将无法解析，页面会塌陷、底部 Tab 栏与弹层定位全部错乱。

### 4. 时间字符串有三种写法

`core/format.js` 的 `toDate()` 已统一处理：

| 格式 | 场景 | 解析方式 |
| --- | --- | --- |
| `2026-10-24 12:30:00` | 业务发生时间 | 按本地时区 |
| `2026-10-24T12:30:00.000Z` | `createdAt` / `updatedAt` | 带时区则按 UTC |
| `2026-10-24` | 仅日期 | 按本地时区 |

不要直接用 `new Date('2026-10-24')`——它会被当作 UTC，导致日期偏移一天。

### 5. 新页面一定要写登录守卫

```js
const page = createPage({ ... });
if (!page) return;   // 未登录时已被重定向，这里必须停下
```

漏掉这行，未登录时页面会在 `null` 上抛 `Cannot read properties of null`。

### 6. 不要覆盖 `.app-body` 的 overflow

`.app-body` 已经带 `overflow-y: auto`，是全应用唯一的滚动容器。
给它加内联 `overflow: 'hidden'` 或把它改成 `display: flex`（同时子元素是 `flex: 1`），
都会让内容溢出但滚不动——登录页就踩过这个坑，注册按钮永远点不到。

页面需要自定义内边距时，只改 `padding`，不要动 `overflow` 与 `display`。

### 7. 支出金额要带负号

流水金额在 store 中一律存正数，正负号由类型决定。
展示时请用 `formatSignedMoney(amount, type)`（支出 `-`、收入 `+`），
不要直接按数值正负拼正负号——那会把支出显示成 `+`。
